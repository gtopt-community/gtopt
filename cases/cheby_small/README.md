# cheby_small — small cases for point-sampled (Chebyshev) stages

Small gtopt cases, each in two time representations, for testing
`Stage.sampling = "point"` and `model_options.storage_integration`:

- `<case>_block.json`: uniform 1 h blocks over the window (classic block
  semantics, no `Block.time`).
- `<case>_point.json`: one point-sampled stage per original stage, on the
  `N + 1` Chebyshev–Lobatto nodes of `[0, H]` (`t_0` = stage start,
  `t_N` = stage end; the periodic `mini/periodic_week` drops `t_N ≡ t_0`
  and has `N` nodes).  `Block.time` = node time `t_k`, `Block.duration` =
  Clenshaw–Curtis weight `w_k` (`Σ w_k = H`).  The grid comes from
  `scripts/plexos2gtopt/week_sampler.py` (`ChebyshevSampler`,
  `kind="lobatto"`, `durations="quadrature"`).  Point cases set
  `battery_storage_integration = reservoir_storage_integration =
  "cc"` (Clenshaw–Curtis, the converter default for point stages,
  `gtopt_shared.point_sampling`; the objectives below are the same with
  `lg4_pos`); block cases keep the per-type defaults.  Ramps use the default `backward` interval slopes.

Every JSON is generated by `scripts/tcheby2gtopt` (do not edit by hand):

```bash
cd scripts
# mini cases + caso2emb (no external data):
python -m tcheby2gtopt library --out ../cases/cheby_small
# + the cases read from the tcheby SQLite test DBs:
python -m tcheby2gtopt library --src <tcheby>/tests/test_dbs \
  --out ../cases/cheby_small
```

## Origin

The validation systems come from the Chebyshev scheduling research code (Matus et al.)
(Chebyshev short-term hydrothermal scheduling, C++), directory
`tests/test_dbs/`: SQLite system/simulation databases and the PLP case
`caso2emb_ver19/`.  The SQLite files were read only (URI `mode=ro`).
The mini cases are new; their objectives are derived by hand.

## Cases

Objectives in $ (`scale_objective = 1`), solved with HiGHS (`--solver
highs`), before the storage envelope rows on point stages (see the flags
below).

| Case | Source | Block obj. | Point obj. | Reference |
|------|--------|-----------:|-----------:|-----------|
| `caso2emb` | `caso2emb_ver19/` PLP files | 135000 | 135000 | PLP 135000 (hand: CT energy) |
| `caso1emb` | `system1_caso1emb_fact.db` + `simu1_caso1emb_fact.db` | 252000 | 247143.292205529 | block by hand |
| `losses` | `system1_losses.db` | 626454.116041310 | 626454.116041310 | 626400 lossless by hand + losses |
| `system2_week` | `system2.db` (9 buses, 262 units, 1 week) | 48407753.8832999 | 46675189.8127262 | regression |
| `mini/battery_ramp` | new | 7260 | 7241.46825689373 | block by hand; point regression (*) |
| `mini/hydro` | new | 27400 | 27400 | both by hand |
| `mini/congested_line` | new | 46000 | 46008.0745048467 | both closed form |
| `mini/uc_minup_ramp` | new (MIP) | 31500 | 33065.9545765050 | block by hand; point regression (backward ramps) |
| `mini/periodic_week` | new | 168000 | 168000 | both closed form |

(*) Battery with a binding `emax` on a point stage: the objective
depends on the banded integration rows; the newer envelope rows may move
it slightly.  The other point cases with storage (`caso1emb`,
`caso2emb`, `hydro`, `periodic_week`) have objectives fixed by a closed
form or an energy argument (levels not binding), so they should not
move.

## Not converted

- `system1_ct.db`, `system1_reszone.db`: DB-reader fixtures, not
  consistent systems.  At the simulation time zero (2016-01-01) reservoir
  Laja starts at `vini = 2.2 hm³` below its scheduled `vmin = 3.3 hm³`,
  line `tmin` schedules (900–1000) exceed `tmax` (67–100), and the 10 MW
  demand is below the unit floors plus the forced waterway flows; both
  conversions are infeasible in gtopt.  The converter still maps their
  schema (hour-keyed schedules, passthrough, overspill, commitment) and
  the unit tests cover it.
- `simu1_uc1.db`, `simu1_ucc1.db`: simulation DBs only (one 12 h stage,
  20 / 64 coefficients, inflow 25 m³/s for `CH_Inf`); no system DB with
  commitment data ships with them.  `mini/uc_minup_ramp` covers unit
  commitment.
- `system_mernc.db` + `simu_mernc.db`: `system2` plus 28 reservoirs,
  158 waterways and 30 hourly inflows; larger than "small".  It can be
  converted with `python -m tcheby2gtopt convert`.
- `LCuts_10_small.db`: Benders cuts on LP column names of the tcheby LP;
  no gtopt counterpart.
- `simu_caso1.db`: a 2 × 48 h stochastic study of `system2`
  (openings with probabilities); `system2_week` uses the full week of
  data in one stage instead.
- `tests/tschedht/ChebyLib_test.cpp`: ported as pytest
  (`scripts/tcheby2gtopt/tests/test_chebylib_port.py`).

## Running

```bash
gtopt cases/cheby_small/mini/hydro/hydro_point.json --solver highs -d out
```

`out/solution.csv` holds `obj_value`; point stages also write
`out/block_time.csv` (node time and weight per block).  Bus duals are
written in $/MWh (already divided by the block weight): on point stages
they are prices AT the node instant `t_k`.
